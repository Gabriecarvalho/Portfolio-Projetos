  <h2 style="font-family:roboto;"> Resumo do Projeto :clipboard:</h2>
  
  <p align="justify" style="font-family:roboto;"> O projeto visa resolver os desafios enfrentados pelo cliente relacionados à dispersão de um grande volume de dados de projetos em diversos sistemas e bancos de dados, o que dificultava a análise e a supervisão geral. A solução proposta foi desenvolver o Synthesi, uma aplicação web baseada em estratégias de Data Warehouse, criada para centralizar e transformar esses dados brutos em informações úteis. Isso foi feito por meio de um ambiente analítico unificado que oferece um seletor intuitivo para uma visão geral de tarefas, custos e materiais utilizados. A plataforma também permite o rastreamento detalhado de solicitações e ordens de compra, o controle de inventário para garantir que o estoque atenda às demandas, e a gestão completa de fornecedores, com filtros avançados e histórico de transações. Essa abordagem proporcionou uma visão consolidada das operações, facilitando a tomada de decisões estratégicas pelos gerentes e garantindo uma administração de projetos mais ágil, eficiente e integrada.

<summary>Front-end codigos exemplos</summary>

<p> Exemplo de um service para o filtros dinâmicos do frontend.
  
```javascript
import { api } from './api';
import type {
  SupplierInfo,
  SupplierListFilters,
  SupplierOrdersResponse,
  SupplierPreviousOrder,
} from '../types/purchase';

type SupplierApiItem = {
  id_fornecedor: number;
  codigo_fornecedor: string;
  razao_social: string;
  cidade: string;
  categoria: string;
  status: string;
};

const toQueryParams = (filters: SupplierListFilters) =>
  Object.fromEntries(
    Object.entries(filters).filter(([, value]) => typeof value === 'string' && value.trim() !== '')
  );

const mapSupplier = (supplier: SupplierApiItem): SupplierInfo => ({
  id_fornecedor: supplier.id_fornecedor,
  codigo_fornecedor: supplier.codigo_fornecedor,
  nome_fornecedor: supplier.razao_social,
  categoria: supplier.categoria,
  cidade: supplier.cidade,
  status: supplier.status,
  ativo: supplier.status.toLowerCase() === 'ativo',
});

const mapSupplierOrder = (
  order: SupplierOrdersResponse['pedidos'][number]
): SupplierPreviousOrder => ({
  codigo_projeto: order.codigo_projeto,
  codigo_pedido: order.codigo_do_pedido,
  nome_material: order.nome_do_material,
  valor_gasto: order.valor_gasto,
  data_pedida: order.data_pedida,
  data_previsao: order.data_previsao,
});

export const supplierService = {
  async getSuppliers(filters: SupplierListFilters = {}): Promise<SupplierInfo[]> {
    const { data } = await api.get('/fornecedores/', { params: toQueryParams(filters) });
    return Array.isArray(data) ? data.map(mapSupplier) : [];
  },

  async getSupplierOrders(codigoFornecedor: string): Promise<{
    fornecedor: string;
    quantidade_pedidos_totais: number;
    quantidade_atrasos: number;
    pedidos: SupplierPreviousOrder[];
  }> {
    const { data } = await api.get(`/fornecedores/${codigoFornecedor}/pedidos/`);

    const response = data as SupplierOrdersResponse;

    return {
      fornecedor: response.fornecedor,
      quantidade_pedidos_totais: response.quantidade_pedidos_totais,
      quantidade_atrasos: response.quantidade_atrasos,
      pedidos: Array.isArray(response.pedidos) ? response.pedidos.map(mapSupplierOrder) : [],
    };
  },
};

```

<h3> Atribuições como Desenvolvedor Back-end</h3>
<p align="justify" style="font-family:roboto;"> 
  No Back-end do projeto Synthesi, fui responsável por estruturar APIs estratégicas para o controle de suprimentos e o monitoramento do progresso das equipes. Desenvolvi um sistema de notificações voltado à gestão de materiais, criando rotas para identificar pedidos atrasados, requisições de peças prioritárias fora do prazo e itens obsoletos em estoque, permitindo que a gestão filtrasse essas informações de forma granular por projeto. 
  <br><br>
  Também atuei na modelagem da camada de análise de tempo, implementando regras de negócio complexas com funções de agregação (<code>Sum</code>) em tabelas de fatos. Além disso, estruturei os serviços e repositórios responsáveis pelas consultas de busca avançada de programas e fornecedores, garantindo o encapsulamento e a modularidade do código.
</p>

  <h5 style="margin-bottom: 8px;">Regras de Negócio e Cálculos</h5>
  <ul style="font-family:roboto; line-height: 1.6;">
    <li><strong>Lista de Tarefas:</strong> Retorna as chaves <code>codigo</code>, <code>titulo</code>, <code>responsavel</code>, <code>estimativa</code> e <code>status</code>.</li>
    <li><strong>Total de Horas por Tarefa:</strong> Campo calculado <code>total_horas_trabalhadas</code> utilizando funções de agregação (<code>Sum</code>) sobre a tabela de fatos correspondente aos apontamentos de horas.</li>
    <li><strong>Evolução Temporal:</strong> Gera e retorna o objeto <code>evolucao_horas</code> (formato dicionário/JSON), estruturando como chave a data (<code>YYYY-MM-DD</code>) e como valor o somatório de horas consolidadas do dia, pronto para alimentar a biblioteca de gráficos no Front-end.</li>
  </ul>
  
  <h5 style="margin-bottom: 8px;">Serviços Adicionais (Services)</h5>
  <ul style="font-family:roboto; line-height: 1.6;">
    <li><strong>Programas e Fornecedores:</strong> Criação de lógicas de negócio na camada de <i>Services</i> dedicadas a processar buscas, aplicar os filtros recebidos pelos parâmetros e estruturar a resposta do banco de dados antes do envio ao cliente.</li>

<h3> Atribuições como DevOps</h3>
<p align="justify" style="font-family:roboto;"> 
  Atuei também na infraestrutura e cultura DevOps do projeto, sendo o responsável por arquitetar e implementar as esteiras de CI/CD (Integração e Entrega Contínuas) para os ambientes de Front-end e Back-end. Utilizando o <b>GitHub Actions</b>, configurei pipelines automatizados que monitoram a branch principal (<code>main</code>). A arquitetura foi desenhada para garantir implantações seguras e sem tempo de inatividade (<i>zero downtime</i>), assegurando que os novos serviços só recebessem tráfego de usuários após aprovação total nos testes e nas verificações de saúde do sistema.
</p>
